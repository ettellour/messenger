# Использование ИИ

Около 70 % кода написала команда (Maksat, Igor, Gosha), около 30 % задач — тесты, проверки, настройку сервера и выкладку — выполнял ИИ-ассистент для программирования. Архитектуру, план (PLAN.md), решения и приёмку результата определяла команда

## Как работали

1. План реализации задал архитектуру, протокол, API, этапы и правила кода. Это файл PLAN.md, по которому велась разработка.
2. Правила кода ИИ получал в каждой сессии: ООП только там, где есть состояние, комментарии на английском и только о причине, ошибки ловятся на границах, без абстракций на один вызов и без сторонних зависимостей.
3. Под отдельные задачи подключались наборы правил:
- решения протокола: форма событий, курсоры истории, отправка файла в два шага;
- чеклист своей реализации WebSocket по RFC 6455;
- проверка безопасности по diff в конце этапов: вывод текста только через `textContent`, флаги cookie, доступ к чужим чатам и файлам, лимит попыток входа;
- тесты только на `node:test`, сервер на случайном порту и временная папка данных;
- чистка diff перед коммитом: лишние комментарии, обёртки, общие имена;
- правила интерфейса во время работы и отдельный проход по нему перед показом, предложения которого применялись только после согласования.
4. Каждое изменение проверялось тестами (сейчас их 191) и вручную в браузере. Находки ИИ сверялись с кодом, прежде чем их исправлять.
5. Второй разработчик проверял проект независимо: запускал его с нуля на Arch Linux, проходил сценарии в Chromium и Firefox, ломал защиты, чтобы убедиться, что тесты это ловят, и заводил найденное в GitHub Issues. Исправления шли отдельными pull request.
